## How to use this register

- Use **[OFFICIAL]** sources for current thresholds, deadlines, policy, schemas, and supported alternatives.
- Use **[LIBRARY]** sources for client configuration and version-specific behavior.
- Use **[COMMUNITY]** sources for troubleshooting patterns only.
- Date-label older sources. Old 100-server language is historical and must not be presented as current policy.

## Cross-source conclusions

These sources support five durable conclusions:

1. **Necessity is intent-specific.** Name the event, operation, or fields—not just the label.
2. **Three proofs are required.** Product necessity, Discord permission state, and runtime Identify configuration are separate.
3. **Current and historical sources must stay separate.** 2026 official pages govern policy; older material explains rollout symptoms.
4. **Interaction-first design is the default alternative.** Commands, components, modals, targeted REST, user installs, and HTTP interactions can remove broad Gateway dependencies.
5. **There is no verified public acceptance-rate table.** Approval is use-case-specific.
